Является входными данными для разработки. Обновляется при изменении логики продукта.

## 2. Семь кирпичиков

### Сервер
Российская локация - обязательна, потому что собираем персональные данные граждан РФ.
Рекомендация: Beget Cloud, 2 ядра / 4 ГБ / 40 ГБ, свежая Ubuntu LTS, публичный IP.
Это **второй** сервер проекта: агент живёт на отдельном зарубежном и сюда не селится никогда.

### Бэкенд
Минимальный: приём формы, валидация, запись в базу, отправка уведомления в Telegram,
выдача данных в админку. Тяжёлой логики нет - это не маркетплейс.

### База данных
PostgreSQL на том же сервере. Таблицы:

- `leads` - заявки: id, направление, имя, контакт, комментарий, источник, дата, статус, отметка спама
- `consents` - согласия: id заявки, тип согласия (ПДн / рассылка), текст версии, дата, IP
- `admin_users` - доступ в админку

**Важно:** галочка согласия хранится не у пользователя, а здесь. Это требование закона,
и его чаще всего забывают.

### Фронтенд
Статические страницы по дизайн-системе JAVATTI, адаптив от 390 до 1440.
Изображения в арках - фирменный приём.

### Внешние сервисы
- Telegram Bot API - уведомления о заявках (отдельный простой бот, не агент)
- Яндекс Метрика - аналитика
- Почтовый сервис - опционально, на втором этапе

Платёжной системы на первом этапе **нет**: продажа идёт через личный контакт после заявки.

### Домен и SSL
Домен в зоне `.ru` или `.com`, регистратор любой кроме reg.ru.
A-запись на IP сервера, сертификат выпускается автоматически и бесплатно.
Для зон `.ru`, `.рф`, `.su` с 1 сентября 2026 регистрация идёт через Госуслуги.

## 3. Юридическая карта (РФ)

Собираем персональные данные - значит действует ФЗ-152.

**Обязательный минимум:**

1. **Хранение на территории РФ.** База с персональными данными физически на российском сервере.
   Считается расположение сервера, а не юрисдикция хостера.
2. **Политика конфиденциальности** - отдельная страница, ссылка в подвале каждой страницы.
3. **Согласие на обработку персональных данных** - обязательный чекбокс в форме,
   без него отправка не проходит. Факт согласия пишется в базу с датой и версией текста.
4. **Согласие на рекламные рассылки** - отдельный чекбокс, **необязательный**.
   Формулировка именно «на рекламные рассылки». Делать его обязательным нельзя.
5. **Куки-баннер** - нужен из-за Яндекс Метрики. С возможностью отклонить, а не только принять.
6. **Уведомление в Роскомнадзор** об обработке персональных данных.
7. **Оферта** - при появлении платных продуктов на сайте.

**Ограничение по Telegram.** В уведомление уходит только факт: «новая заявка на направление X».
Имя, телефон и почта не передаются - это была бы трансграничная передача данных.
Сами данные остаются в базе на сервере, смотреть их - в админке.

**Юридический статус владельца: ИП.** Что из этого следует:

- Оператором персональных данных выступает индивидуальный предприниматель, а не физлицо
  и не организация. Во всех документах указываются ФИО, ОГРНИП, ИНН и адрес для корреспонденции.
- Сервер регистрируется на ИП, тип персоны при заказе - физическое лицо
  (у хостеров ИП проходит именно так).
- Домен регистрируется на ИП. При выборе типа персоны у регистратора указывается «ИП»,
  если домен должен принадлежать бизнесу.
- Уведомление в Роскомнадзор об обработке персональных данных подаётся от имени ИП.
- Оферта нужна, как только на сайте появляется оплата. Пока продажа идёт
  через личный контакт после заявки - обязательной оферты нет, но черновик готовим заранее.
- Онлайн-касса потребуется при приёме оплат на сайте. На текущем этапе не нужна.

## 4. Карта страниц

| Файл | Задача | Целевое действие |
|---|---|---|
| `index.html` | Объяснить систему, привести в клуб | Разбор |
| `rizq.html` | Показать приложение и журнал | Установить приложение |
| `community.html` | Объяснить ценность сообщества | Заявка на вступление |
| `fashion.html` | Показать бренд одежды | Переход в магазин |
| `business-school.html` | Продать клуб и программы | Вступление в клуб |
| `consulting.html` | Продать личную работу и автоматизацию | Заявка на разбор |
| `thanks.html` | Подтвердить приём заявки | - |
| `contacts.html` | Дать связаться, показать реквизиты | Заявка |
| `privacy.html` | Политика конфиденциальности | - |
| `consent.html` | Согласие на обработку данных | - |
| `offer.html` | Оферта | - |

Страница «Спасибо» - отдельная, с реальным адресом. О ней забывают чаще всего,
а без неё нельзя настроить цель в аналитике.

**Правило по ссылкам.** В навигации и подвале не должно быть ссылок на несуществующие
страницы. Битая ссылка на юридический документ хуже её отсутствия: она обещает то,
чего нет, и это видно проверяющему.

## 5. Админка

Простая, под одного пользователя:

- список заявок с фильтром по направлению и статусу
- отметка «обработана»
- выгрузка в CSV
- папка «Спам» - подозрительные заявки не удаляются молча, а складываются сюда
- кнопка **«Удалить ПДн»** по конкретной заявке - требование закона о праве на удаление

---

## 6. Проверка перед запуском

- отправить мусорную заявку и убедиться, что она не прошла в основной список
- отправить корректную и убедиться, что уведомление пришло, а данные легли в базу
- пройти все переходы: из каждой страницы есть путь назад и путь к заявке
- проверить формы на телефоне
- проверить, что при ошибке пользователю видно, что именно не так
- отклонить куки и убедиться, что Метрика не грузится
